# URA EFRIS Integration & Compliance
*(Critical for Uganda operations. EFRIS (Electronic Fiscal Receipting and Invoicing Solution) is mandatory.)*

## Overview
All tax invoices generated by JCIL must be transmitted to the Uganda Revenue Authority (URA) via EFRIS. 

## Implementation Rules
1. **Invoice Generation**: Invoices are generated *only* when an order is `CONFIRMED` and payment is `RECONCILED` (or at dispatch, depending on JCIL accounting policy).
2. **EFRIS Payload**: The backend must format invoice data into the exact JSON/XML schema required by URA EFRIS.
3. **Device Info**: The system must store the EFRIS `DeviceID` and `TIN` (Tax Identification Number) in secure environment variables.
4. **Synchronization**: 
   - Use a background job (e.g., BullMQ) to send invoices to URA. 
   - Do not block the user interface waiting for URA's response. 
   - If URA is down, queue the invoice and retry with exponential backoff.
5. **Inquiry/Validation**: Before generating an invoice, the backend can optionally query EFRIS to validate the Client's TIN.

## Data Protection Act 2019 (Uganda)
- **Data Minimization**: Only collect client data strictly necessary for B2B transactions and URA compliance.
- **Consent**: The client onboarding flow must include a checkbox for the JCIL Data Privacy Policy.
- **Right to be Forgotten**: Implement a soft-delete mechanism. Hard deletion is restricted due to URA's 10-year record-keeping requirement for tax invoices.
